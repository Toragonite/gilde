Preview macOS · Apple silicon Apache-2.0

See and steer your coding agents from one window.

Gilde is an agent-centred desktop IDE for macOS. It starts and supervises agent CLIs — claude, codex, cursor-agent and agy — shows the sessions you started elsewhere, and keeps one ranked list of what needs you: an approval, a question, an error, a reply.

For developers who run several coding agents across several projects at once. The orchestrator is optional.

Build from source View on GitHub

A preview, distributed as source. Local only. No telemetry.

The problem

Many agents, many windows, and one of them is waiting for you.

Sessions are everywhere

Agents run in terminals, in editors and in the background, across projects and accounts. Finding out which one is doing what means opening each of them.

Requests wait unseen

An agent that asks for permission or asks a question stops until someone answers. While you work in one window, the request in another waits.

Processes outlive their work

Ended sessions and teams can leave agent processes and tool servers running. They keep their memory, and nothing points at them.

Capabilities

What Gilde does

⌘0Home

One list of what needs you

Home opens on the one thing that needs you most, then the next few, with counts for everything else. Answer it right there, put it off with Later, or go to the next one.

  • Needs approval Needs answer Error New reply No progress
  • ⌘J goes to the next item from anywhere; L puts the current one off.
  • Usage limits, accounts that need a new sign-in, and leftover processes show up here too.
  • A notification can tell you when a session needs you. It carries no conversation text unless you turn on details.

Conversation · Terminal · Turn by turn

Three ways to drive a session

Sessions that Gilde starts can be driven from the app. Conversation is a structured chat with approval cards, for claude. Terminal is the agent's own screen inside Gilde, with approval cards read from that screen. Turn by turn runs codex, cursor-agent or agy one run per turn.

  • An approval card offers Allow once, Deny, and Deny and say why — and, where the agent allows it, Always allow a command pattern in this session. Use the mouse or the number keys.
  • A new session can start in its own git worktree and branch. The Changes view commits, merges or discards that worktree.
  • Open in IDE and Diff in IDE hand a session's folder or a change to your editor.

⌘DAdd to split

Up to six sessions side by side

Split puts two to six live sessions in tiles. ⌘1…⌘6 focus a tile, ⌥⌘ with an arrow moves to the tile beside it, ⇧⌘⏎ zooms one.

  • Sessions started elsewhere — in a terminal, an editor or the background — are shown as Watching. Gilde says where they run and never types into them.
  • Focus moves only when you ask.

Panes · Board · Floor

Agent teams as panes, a board or a floor

A team's lead and members open as Panes, as a Board of tasks and messages, or as a Floor: a pixel-style plan with a room per project and a desk per agent, where shelves hold the work to do and the work done. The Floor screen shows every agent across your projects at once.

  • When Gilde starts a team, its teammates open as panes in Gilde, where you can answer and message them.
  • The member the others wait on is marked as the bottleneck.
  • If Claude Code Orchestrator is installed, its teams appear read-only: they are run by the orchestrator and messaged from their lead.

⇧⌘FHistory

Past sessions, searchable

History lists past sessions of the agents on this Mac, including the ones Gilde did not start. Search titles and first prompts, filter by project, agent, time, account and where a session ran, then read it, continue it in Gilde, or continue a copy.

  • Each agent's own retention applies: Gilde lists what is still on disk.

⇧⌘AAccounts and health

Accounts, quota and leftover processes

Each account's usage windows with their reset times, the account new sessions use by default, the memory and running time of every session, and the processes ended sessions left behind — on one screen.

  • Add another account by its configuration folder and choose the default per agent.
  • Clean-up stops leftover processes after you confirm. Gilde never stops a process it cannot identify, and never stops a background job on its own.
  • With the orchestrator installed, its accounts are listed here too.

How it works

One core holds every privilege. The window only renders.

  1. Gilde finds your sessions. It reads the agents' own session files without writing them and looks at the process table, so sessions you started in a terminal, an editor or the background appear as Watching.
  2. You start a session from Gilde. Pick a project, an agent and an account, or take the defaults. Gilde starts the CLI in a terminal it supervises, as a structured conversation, or turn by turn — in its own worktree if you want one.
  3. Requests come to you. Approvals, questions, plans, errors and new replies join one ranked list. Answer on Home or in the session; a notification can point you there.
  4. Processes stay accounted for. Every process Gilde starts is registered before it runs, and Gilde stops what it started when you stop the session or quit the app. What ended sessions leave behind is listed as leftovers until you clean it up.

Security and privacy

Your work stays on your Mac.

Local only

Gilde sends your data nowhere. It has no telemetry, no analytics, no update check and no network client of its own; the only network traffic is what the agent CLIs you run produce.

No conversation text on disk

Messages, tool input and output, titles and prompts live in memory only. The state database holds metadata — ids, states, timestamps, counts — and a schema test fails on any column that could hold content.

Credentials are never opened

The agents' folders are read-only to Gilde, and a path filter refuses key files, lock files, token and OAuth files before any open. Gilde never signs in for you and does not read other processes' environment values.

Watching means hands off

A session started elsewhere is shown, never typed into. Clean-up stops only leftover processes it can identify, after you confirm.

The limit of any coding agent

Agents run as your macOS user. A worktree keeps work apart and protects against accidents; it is not a security boundary. An agent that can run shell commands can read your user's files, so read an approval card before you allow it, and do not run agents on a repository whose content you do not trust.

Found a vulnerability? Report it privately: on GitHub, Security → Report a vulnerability, or by e-mail to toragonite@gmail.com. Please do not open a public issue for it.

Requirements

What you need

To run it

Mac
Apple silicon (M1 or later), macOS 11 or later — verified on macOS 14.6
Agents
at least one agent CLI, installed and signed in: claude, codex, cursor-agent or agy. Conversation mode needs claude 2.1.268 or newer; older versions run in Terminal mode.
Optional
git for worktrees and the Changes view, an IDE for Open in IDE, and Claude Code Orchestrator for its teams and accounts

To build it

Xcode CLT
Xcode Command Line Tools — compiler, linker and codesign
Rust
stable 1.95 or newer, from rustup (verified with 1.96.1)
Node.js
20.19+ or 22.12+, with npm 10 or newer
Network
for the first build: npm packages, Rust crates and the pinned Node runtime from nodejs.org
Disk
a few GB free for the Rust build directory

Not supported by this build: Intel Macs (a Rosetta shell on Apple silicon included), Linux and Windows. The build pins one Node runtime, for macOS on arm64, and the process supervision reads macOS interfaces.

Build from source

Build Gilde Code on your Mac

There is no binary download. The preview is distributed as source, and these are the repository's own scripts.

Verified on macOS (Apple silicon)

  1. Get the source

    git clone https://github.com/Toragonite/gilde.git gilde
cd gilde

  2. Install the dependencies

    npm ci
(cd src-tauri/sidecar && npm ci)

    The app and its sidecar have separate lockfiles.

  3. Fetch the pinned Node runtime

    npm run node:fetch

    Downloads Node v20.19.2 for darwin-arm64, checks it against the published SHA-256 and the hash pinned in scripts/fetch-node.sh, and ad-hoc signs it. A mismatch stops the build. Once installed, later runs do not touch the network.

  4. Build the sidecar

    npm run sidecar:build

    Bundles the sidecar and runs the check that no process is started outside its two supervised modules.

  5. Build the app

    npm run tauri build

    Checks that every manifest carries the same version, runs steps 3 and 4 again (they do nothing when their output is current), builds the frontend, compiles the app in release mode and ad-hoc signs the bundle. The first build takes several minutes. Add -- --bundles dmg for a disk image as well.

Result src-tauri/target/release/bundle/macos/Gilde Code.app Drag it to Applications. An app you build yourself carries no quarantine attribute, so it opens without a Gatekeeper prompt.

For development: npm run tauri dev, or VITE_GILDE_SHOWCASE=1 npx vite for the UI on demo data in a plain browser. The full guide, with tests and troubleshooting, is BUILDING.md in the repository.

FAQ

Questions

Does it need Claude Code Orchestrator?

No. Gilde works on its own with the agent CLIs you have. When the orchestrator is installed, its teams and accounts appear read-only; without it, nothing about it renders.

Which agents does it work with?

claude, codex, cursor-agent and agy. claude runs in Conversation mode (2.1.268 or newer) or Terminal mode; the other three run turn by turn or in Terminal mode.

Can it answer a session I started in a terminal?

No. A session started elsewhere is Watching: Gilde shows it and says where it runs, but never types into it. From History you can continue a past session in Gilde, or continue a copy.

Does it change my repository?

The agents you start change files as they work, as they would in a terminal. Gilde itself writes to git only when you ask: a new worktree for a session, or a commit, merge or discard in the Changes view. Its own settings and state live in ~/Library/Application Support/com.toragonite.gildecode.

Does it send telemetry?

No. The code has no telemetry, no analytics and no update check. Building it downloads packages and the pinned Node runtime once.

Does it run on Linux or Windows?

Not in this build. It is built and tested on macOS on Apple silicon; the bundled Node runtime is pinned to that platform and the process supervision uses macOS interfaces.

Why is there no download?

This preview is distributed as source only: there is no Developer ID–signed or notarized download and no auto-updater. You build the app on your own Mac with the steps above; to update, pull and build again.
